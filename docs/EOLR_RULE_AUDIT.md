# EOLR 中文规则逐条核对

核对依据为 `src/data/EOLR.json` 中用户整理的中文识别条件。原始中文、名称、解法与示例打乱均未修改。独立项目只保留运行时使用的修正规则 `src/data/EOLRRecognitionRulesFinal.json`。以下51条核对结论沿用原项目；测试与启动方式已更新为独立项目。

## 判断顺序

1. 只看六个LSE位置的EO，先确定大类。先数U层与D层错误棱数量；U层为2时，再用相邻/相对区分2a/2o。
2. 只在已经确定的大类中判断中文条件。传入的大类若与实际状态不同，返回未匹配；不跨类搜索。
3. 中文条件绑定到各自的棱，再允许两块LR交换身份。LR只指UL、UR两块棱，不包括已完成搭块中的其他含L/R色棱。
4. 只有3/1的“坏”有兜底，且必须在3/1内其他四条均未命中后使用。多条规则冲突时返回未匹配，不按文件顺序选择。

## 观察基准与条件解释

U层相邻仅指UF、UL、UB、UR组成的四边环；“上方”是UF/DF或UB/DB，独立于相邻关系。M层为UF、UB、DF、DB；不在M层为UL或UR。色相正确/错误沿用现有魔方模型的eo=0/1，与51条中文示例逐一核对一致。

内部比较的EO顺序为UF、UL、UB、UR、DF、DB。1/1的比较模板以UF、DB为错误棱位置；3/1的比较模板以UF、UL、UR、DF为错误棱位置，箭头顶端为UF。其他大类采用下表规范EO。整颗换向仅用于内部比较，不作为用户操作要求。必要的U、U'、U2顶层调整在答案中单独提示，揭晓不自动转动魔方。中文识别与处理按原文展示；M、M'或M2会改变EO，不能当作等价识别视角。

## 源资料中的解释与差异

`1/1－最好`的“其中一个在M层”按**恰好一个**解释：另一条“坏”明确对应两个LR都正确且都在M层，“两边”对应两者都不在M层。这个解释使三条互斥且覆盖完整。原position字段列出的UR/DB在规范视角中包含错误DB棱，不符合“两个LR都正确”；UB/UR则符合中文但未列出。实现以中文为准，保留原始位置栏供复核，不将它作为判断条件。

其他位置栏也有仅列示例的情况，例如2o/2的Decent仅列DF，但中文允许DF或DB。下表列出按中文推导的完整规范位置集合。解法文字中的每一步教学操作不是本次规则检查的验证目标；此次核对的是识别条件和匹配结果。

## 验证结果

- 51条原始打乱逐条识别通过；所有51个子类均可命中。
- 独立人工整理9个大类×15个LR位置的期望表，逐项比对。

- 检查每个规范组合的LR身份互换、4种U转向、y2视角，以及另外4块LSE棱的24种排列。

- 独立出题器验证：遍历184,320个合法LSE状态；逐条生成51类子情形，并将生成打乱重新应用到真实魔方模型验证。抽检图坐标、棱块排列、EO、中心与角块状态一致。
